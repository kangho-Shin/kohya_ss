# Windows Photo Faceswap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 별도 Windows RTX 3080 PC에서 실행할 개인용 사진 얼굴 교체 프로그램과 선택적 Stable Diffusion 보정을 제공한다.

**Architecture:** Tkinter UI는 작업 큐를 통해 이미지 처리 엔진을 호출한다. 모델 준비, 교체, 보정과 파일 저장을 독립 모듈로 구분하고 사진 처리는 로컬에서 수행한다.

**Tech Stack:** Python 3.11, Tkinter, Pillow, NumPy, OpenCV, InsightFace, ONNX Runtime, 선택적 PyTorch·Diffusers, pytest.

**Spec:** docs/superpowers/specs/2026-10-18-faceswap-design.md

## Global Constraints

- 본인 전용이며 실행 대상은 이 클라우드가 아닌 별도의 Windows PC이다.
- 원본 파일은 덮어쓰지 않는다. 동영상, 웹캠, 일괄 처리는 첫 버전에 포함하지 않는다.
- 사진을 원격 추론 서비스로 보내지 않는다.
- 보정 끄기를 기본값으로 하고 얼굴 교체 결과 자체도 보존한다.
- 현재 클라우드는 Linux이며 NVIDIA GPU가 확인되지 않았다.
- 모델·개인 사진·가상환경은 커밋하지 않으며 TLS 검증을 유지한다.

## Review Focus

- 한글·공백 경로와 EXIF 회전 사진도 올바른 방향으로 읽고 저장한다.
- 얼굴이 없거나 번호가 유효하지 않으면 결과 저장 없이 설명한다.
- CUDA 제공자 초기화 실패를 CPU 실행으로 숨기지 않고 실행 장치를 표시한다.
- 이미지 재선택·처리 실패 이후 이전 결과를 새 결과처럼 저장하지 않는다.
- 실패한 모델 다운로드는 완성 파일을 남기거나 기존 정상 모델을 손상시키지 않는다.

### Task 1: 이미지 입출력과 모델 준비

**Files:** `faceswap_app/images.py`, `faceswap_app/models.py`, `requirements.txt`, `requirements-dev.txt`, `.gitignore`, `tests/test_images.py`, `tests/test_models.py`.

**Interfaces:** `load_image(path: Path) -> np.ndarray`는 EXIF를 반영한 BGR 이미지를 반환한다. `save_png(image: np.ndarray, destination: Path, originals: tuple[Path, ...]) -> Path`는 원본 덮어쓰기를 거부한다. `require_models(model_dir: Path) -> ModelPaths`는 누락 모델을 명시한다. 모델 준비 CLI는 사용자 제공 ONNX 경로와 공식 배포처를 안내한다.

- [ ] 한글 경로, EXIF 회전, 원본 덮어쓰기, 손상 이미지, 누락 모델, 중단 다운로드 테스트를 먼저 작성한다.
- [ ] `python -m pytest tests/test_images.py tests/test_models.py -q`로 구현 전 실패를 확인한다.
- [ ] 의존성 호환성과 공식 모델 출처·라이선스를 조사하고 버전을 고정한다. 확인되지 않은 교체 모델의 자동 다운로드를 구현하지 않는다. 다운로드 구현 시 임시 파일, HTTP 오류 처리, 공식 체크섬 검증 후 교체를 사용한다.
- [ ] 위 인터페이스를 구현하고 같은 테스트 통과 후 커밋한다.

### Task 2: 얼굴 탐지·교체와 선택적 보정

**Files:** `faceswap_app/engine.py`, `faceswap_app/refine.py`, `requirements-sd.txt`, `tests/test_engine.py`, `tests/test_refine.py`.

**Interfaces:** `FaceEngine(model_dir: Path, device: str)`; `detect(image: np.ndarray) -> list[Face]`; `swap(source: np.ndarray, target: np.ndarray, source_index: int, target_index: int) -> SwapResult`. `SwapResult`는 교체 이미지, 선택 얼굴 bbox, 실행 제공자 이름을 포함한다. `refine(image: np.ndarray, bbox: tuple[int, int, int, int], model_dir: Path, strength: float = 0.2) -> np.ndarray`는 로컬에 준비한 SD 모델로 경계만 보정한다.

- [ ] 얼굴 없음, 잘못된 번호, 다중 얼굴 정렬, CUDA 초기화 실패, 크기가 작은 얼굴, 경계 밖 bbox와 보정 영역 밖 픽셀 보존 테스트를 작성한다.
- [ ] 해당 테스트가 구현 전 실패하는지 확인한다.
- [ ] 모델을 지연 로딩하고 실행 제공자를 확인한다. OOM은 재시도 루프 없이 설명한다. 교체 세션 해제 후 FP16 SD 모델을 로딩하고 제한된 보정 영역을 사용한다.
- [ ] 단위 테스트와 실제 공급 가능한 모델의 CPU 탐지·교체를 실행한다. 외부 전제 조건이 없으면 미실행으로 기록한다. 검증 후 커밋한다.

### Task 3: 데스크톱 UI와 작업 상태

**Files:** `faceswap_app/gui.py`, `faceswap_app/jobs.py`, `faceswap_app/__main__.py`, `tests/test_jobs.py`.

**Interfaces:** `JobRunner.submit(callable)`는 단일 작업만 허용하고 큐로 성공·실패를 전달한다. `main() -> None`은 Tkinter 창을 연다. UI 상태는 입력 변경 시 결과를 지우고 처리 중 파일 선택과 중복 실행을 막는다.

- [ ] 중복 실행 거부, 예외 이후 재실행, 입력 변경 후 결과 무효화, 성공·실패 이벤트 전달 테스트를 먼저 작성하고 실패를 확인한다.
- [ ] 사진 두 장 선택, 번호가 표시된 얼굴 미리보기, 얼굴 선택, 교체, 선택적 보정, PNG 저장과 장치 표시를 구현한다. Tk 위젯은 메인 스레드에서만 갱신한다.
- [ ] 테스트를 통과시키고 디스플레이가 있으면 GUI 시작을 검증한다. 디스플레이가 없으면 명확하게 미검증으로 기록하고 커밋한다.

### Task 4: Windows 전달과 재사용 클라우드 설정

**Files:** `install.bat`, `run.bat`, `install-sd.bat`, `README.md`, `scripts/doctor.py`, `scripts/smoke.py`.

**Interfaces:** 배치 파일은 `%~dp0`에서 실행하고 `py -3.11`로 `.venv`를 만든다. `doctor.py`는 비밀 값 없이 Python 버전, 패키지, ONNX 제공자, 모델 준비 상태를 보고하며 필수 항목 누락 시 비영 종료한다. `smoke.py --source PATH --target PATH --output PATH --model-dir PATH`는 GUI 없이 실제 교체를 수행한다.

- [ ] 설치 중 실패 시 비영 종료, 경로에 공백이 있는 경우, 모델 없는 상태 진단을 점검한다. README에 Windows 설치, 공식 모델 준비, 실행, SD 추가 설치, GPU 오류 해결과 검증 한계를 한국어로 작성한다.
- [ ] 클라우드 가상환경에 의존성을 설치하고 전체 테스트와 가능한 실제 smoke를 실행한다. 실패 원인을 조사하고 설치 문제를 수정한다.
- [ ] 실행한 설치·검증 명령과 기존 체크아웃 사용 지침을 환경 초안의 `install_script`·`start_skill`에 저장한다. 모델 준비가 막혀 있으면 환경 준비 완료라고 표시하지 않는다.
- [ ] 전체 변경 검토와 테스트 결과 확인 후 코드·문서를 커밋하고 기존 GitHub 원격의 브랜치를 확인한다. 비어 있는 원격에는 로컬 커밋을 `main`으로 push한다. 기존 원격 커밋이 생겼다면 강제 push 없이 보존한다.
- [ ] GitHub 원격 커밋 조회로 업로드를 확인하고 사용자에게 저장소 주소, 설치 순서와 미검증 항목을 보고한다. Windows EXE 생성은 이 Linux 환경에서 완료했다고 주장하지 않는다.
