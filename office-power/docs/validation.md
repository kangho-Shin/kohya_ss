# 검증 기록

2026-10-20, 사용자 요청에 따라 Visual Studio 2022용 .NET SDK 8.0.426 / 런타임 8.0.32 / C# 12 / OfficePower.sln으로 변경했다. SDK는 Microsoft 공식 릴리스 메타데이터의 SHA-512와 다운로드 파일을 대조했다. .NET 8에서도 아래 24개 테스트와 전체 솔루션 빌드가 통과했다.

## 통과

- C# 테스트 24개, 실패·건너뜀 0개.
- 매직 패킷 102바이트와 MAC 반복 검증, 실제 UDP 소켓 송수신.
- 잘못된 MAC·IPv4 거부, 등록 파일 저장·복원과 손상 파일 보존.
- 실제 Kestrel HTTPS 서버와 인증서 SHA-256 고정 클라이언트 통신.
- 정상 인증, 잘못된 인증키·다른 인증서 거부, 통신 시간 초과.
- 중복 종료 거부, 동시 요청에서도 종료 실행기 1회 호출, 실패 후 재시도, 종료 취소에 대비한 2분 중복 창 만료.
- 한 PC의 HTTP·UDP 오류가 다른 PC 처리를 막지 않음. 관리 PC 자체는 마지막에 처리.
- Release 솔루션 빌드: 경고 0, 오류 0.
- Agent와 WinForms Controller의 Windows x64 self-contained EXE 게시.

테스트는 실제 OS 종료 대신 테스트 대역을 사용했다. 사무실 PC에 종료 패킷을 보내지 않았다.

## 리뷰 수정

독립 리뷰에서 발견한 Windows Schannel의 ephemeral 인증서 비호환을 수정했다. Windows는 MachineKeySet(영구 보존 플래그 제외)을 사용하며 테스트도 실제 PFX 로더를 거친다. Linux 성공만으로 Windows TLS를 검증했다고 간주하지 않는다.

서비스 재설치의 실행 경로 따옴표 처리는 CIM API로 바꾸고 저장된 경로를 검증한다. 인증 디렉터리와 하위 파일의 소유자·권한을 제한하고 reparse point를 거부한다. Windows CI에는 실제 설치·인증서 고정 HTTPS 상태 확인·재설치 인증 유지·파일 권한·실행 경로 확인을 추가했다. 이 테스트도 종료 API를 호출하지 않는다.

## 현재 클라우드에서 검증하지 못한 항목

- 실제 Windows 설치, Windows 서비스 수명과 Schannel, DPAPI·방화벽 동작. GitHub의 Windows CI 결과는 별도로 확인한다.
- WinForms 화면의 실제 클릭·렌더링과 VS2022 폼 디자이너에서의 편집.
- 사무실 하드웨어의 WOL 부팅, BIOS·랜카드 설정, 실제 Windows 종료.
- 실행 파일 코드 서명. 현재 배포본은 자체 빌드한 서명 없는 프로그램이다.

## 남은 작은 제한

다중 PC 요청은 순차 처리하며 처리 중 창 닫기·취소를 제공하지 않는다. 연결이 안 되는 PC가 많으면 각 PC의 통신 제한 시간만큼 기다려야 한다. 관리 PC 자체를 마지막에 처리하므로 다른 PC 요청보다 먼저 종료하지 않는다.

## 구현 중 결정

추가 설계 승인은 사용자 요청에 따라 생략했다. 기존 얼굴 교체 프로젝트를 보존하고 office-power를 별도 폴더로 추가했다. 사용자의 VS2022 조건에 맞춰 .NET 8과 기본 .sln 형식을 사용하며, 실행 PC에 런타임이 필요 없도록 self-contained로 게시한다. 인증서는 공용 CA 대신 PC별 고정 지문으로 명시적으로 신뢰한다. 이 인증 파일을 잘못 전달하면 다른 PC를 등록할 수 있으므로 안전한 전달이 필요하다.

사용자의 추가 요청으로 WPF를 제거하고 WinForms로 전환했다. GitHub의 자동 빌드·자동 릴리스를 중단했으므로 전환 후 원격 Windows CI를 자동 실행하지 않았다. 클라우드의 Windows 타깃 빌드와 코어·서비스 테스트를 검증하고 실제 폼 실행 검사는 수동으로 남겼다. 기존 Windows CI의 서비스 설치·재설치·인증서 고정 HTTPS 검사는 전환 전 코드에서 통과했다. 에이전트·인증 로직은 UI 전환에서 변경하지 않았다.
